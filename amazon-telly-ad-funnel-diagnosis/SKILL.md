> **用途**：针对单个款（父体，含全部变体）做近 30 天广告诊断，输出一份「先结论、后证据」的 31 块诊断报告 + 按先后排好的行动清单。
> **原则**：只读数据，不修改任何广告；每个判定都必须给出数值、阈值和对应标签。
> **来源**：根据博主「多多宝鱼儿」的 15 张截图反推。截图里能直接看到的规则标 ✅，根据标题或数字推断的标 🔶，审核时请重点看 🔶。

## v0.2 审核决议（2026-10-16）

1. **决策顺序保持不变**：利润 / 退货闸门优先，闸门没过不建议扩量。
2. **阈值不通用，每个款单独设定**：真实保本 ACOS、退货率标准与拦截线、推排名目标 ACOS 都是「按款计算或由用户指定」的参数。截图里的 22.6% / 25% / 32.5% / 45.2% 只是 8028 款的案例值。参数缺失时先问用户，不默认套用。
3. **推排名 = 有时限、有预算上限的亏损实验**：开跑前必须写清目标 ACOS、实验天数（默认 14 天）、预算上限、复盘日期。到期自然位没前进 → 降价或停。
4. **搜索词处置从严**：只有证据够的词才进「降价 / 否定」，其余一律「观察」；词根只输出「人工语义复核候选」，不直接否定。
5. **排名和自然单只能谨慎推断**：第三方没查到位置 ≠ 没有排名，结论写「待复核」；自然单 = 总销量 − 广告订单只是估算（广告报表按点击归因、店铺报表按下单日期），只看趋势。
6. **范围扩展**：单父体报告之外增加「账户总览（多父体）」；广告类型从 SP 扩展到 SB / SD，各用自己的归因口径（见第 8、9 节）。

## v0.3 植入决议（2026-10-17 · 吸收旧版 amazon-ad-strategy-framework v1.13.28）

1. **否词两段式**：**初筛 = 1.5 ÷ 基准 CVR**（可按款改为 1 ÷ CVR），**终判 = 二项检验 90%**：n ≥ ln(0.10) ÷ ln(1 − 基准 CVR) ≈ 2.3 ÷ CVR。当前走**低预算路径**，初筛达标即可进否定（标「初筛级」），见 3.6。v0.2 第 4 条的「从严」改为：**花钱从严、否定形式从严**（否词组 / 精准，不直接否词根）。
2. **样本量规矩保留 v0.2 口径**（3.5 不替换），只补充「近 7 天归因未闭合」和置信区间标注。
3. **新增**：可承受 CPC、达标线、ACOS 三级口径、广告位平台事实、常数分级（3.1 / 3.7 / 3.9）；诊断入口切时间轴（1、7）；趋势三态（3.10）；动作纪律、回填闭环、载体与架构（5.1–5.3）；已停活动死因分类（3.8）。
4. **不植入**：洞察六层模型 / 自我演进协议、产品特定的 C 级常数、参考骨架 ≤8 活动模板、新品 L0 架构四步。

## 0. 何时使用

- 用户说「诊断一下 XX 款的广告」「这个款广告该不该调」「帮我看下广告哪里漏钱」。
- 对象：一个父体 ASIN（或一组 SKU），站点、时间窗口默认近 30 天（截止到最近一个数据完整日）。

## 1. 核心思想（业务逻辑主线）

1. **先问「问题在不在广告」，再动广告**。先算真实保本线，再过三道闸门（点击率 → 转化率 → 退货率）。任何一道被拦截，广告侧**只做减法**：不加预算、不抬出价、不扩词。✅
2. **钱按「投放目的」分开算，容忍度不同**。推排名可以亏（有上限），找词和截流必须不亏。✅
3. **逐层定位漏钱的地方**：广告位 → 变体 → 关键词 / 搜索词，每一层都单独算，不用一套参数打全款。✅
4. **零单词先分「买贵了」还是「买错了人」**，处置相反：买贵了就降价，买错了人才否定；否定默认用词组，词根只作人工复核候选，并做零误伤校验（v0.3 调整，见 3.6）。✅
5. **回顾历史**：已暂停的活动和关键词分成「停得对 / 停早了 / 停可惜了」，把经验沉淀为规矩。✅
6. **行动清单按先后排**：产品问题 → 止损减法 → 观察 → 恢复 → 加法暂缓。做完一条再做下一条。✅
7. **第一刀先切时间轴**：先分「一直差」还是「变差了」，两种的根因池完全不同。🆕
   - 一直差 → 结构根因：选品 / listing / 词不准 / 承接力。
   - 变差了 → 外部四查：差评、季节、跑歪（自己改了什么）、竞争环境；再落到内部指标层。
   - 广告层用 **CTR × CVR 四象限**定位：CTR 低 CVR 高 = 曝光位置 / 主图问题；CTR 高 CVR 低 = 承接问题（详情页、价格、评价）；双低 = 词不准；双高 = 放量候选。
8. **截面说「现在多少」，趋势说「往哪走」**：任何保留 / 关停 / 加减预算结论，先回答它在变好还是变坏（3.10）。🆕
9. **每个动作都要能被验证**：动作编号 + 数值化判定线 + 观察期 + 回填（5.2）。🆕

## 3. 规矩表（全报告的判定口径）

### 3.1 保本线

| 指标 | 公式 | 截图示例 |
| --- | --- | --- |
| 名义保本 ACOS（不算退货） | (平均成交价 − 货值头程 − 佣金 − FBA 费) ÷ 平均成交价 | 51.9% ✅ |
| 真实保本 ACOS（近 90 天实际入账） | (销售额 − 退款 − 各项费用 − 发出去的货值 + 退回来的钱和可再卖的货) ÷ 销售额 = 留下来的毛利 ÷ 销售额 | 22.6% ✅ |
| 推排名目标 ACOS（实验上限） | 由用户按款设定，并同时设定实验天数、预算上限；未设定时先询问。可参考值：真实保本 × 2 | 45.2%（8028 款案例值，不可默认套用） |
| 零单花费阈值 | 平均成交价 × 真实保本 ACOS（即一单最多能花的广告费） | $40.63 × 22.6% ≈ $9.17 ✅ |
| 达标线（加预算门槛） | 真实保本 ACOS × 75% | 22.6% × 75% ≈ 17.0% 🆕 |
| 可承受 CPC（每个词单独算） | 真实保本 ACOS × 平均成交价 × 该词 CVR（= 一次点击最多能花多少） | $40.63 × 22.6% × 2.6% ≈ $0.24 🆕 |
| 买得起判定 | 可承受 CPC ≥ 建议竞价下限 → 买得起；否则该词在本款利润下买不起，不靠加价硬抢 | 🆕 |
| 零单点击阈值 · 初筛 | **1.5 ÷ 基准 CVR**（低预算路径默认；可按款改 1 ÷ CVR）。零单到这里，碰巧零单的概率约 22%（1÷CVR 时约 37%） | 1.5 ÷ 2.6% ≈ 58 次 🆕 |
| 零单点击阈值 · 终判 | 二项检验 90%：ln(0.10) ÷ ln(1 − 基准 CVR) ≈ 2.3 ÷ CVR | ≈ 88 次 🆕 |

**目标 ≠ 盈亏线**：目标 ACOS 是管理要求，真实保本是生死线；判「亏不亏」只用保本线，误把目标当盈亏线会关掉赚钱的活动。🆕

**客单价必须用真实成交价**（含折扣、优惠券后），不能用标价或固定值做全盘测算。🆕

**所有阈值均为按款参数**：退货率标准与拦截线、基准点击率 / 转化率、推排名目标 ACOS 写进报告的「本款参数」表，并标明来源（计算 / 用户指定 / 类目数据）。

注意：佣金按发货时的销售额收，退款时只退一部分，所以退货率越高，真实保本线比名义保本线低得越多。✅

### 3.2 三道闸门（指数 = 我 ÷ 基准）

| 闸门 | 通过 | 偏低 / 偏高（可修边） | 拦截 | 没过归谁管 |
| --- | --- | --- | --- | --- |
| ① 点击率 | 指数 ≥ 1 | 0.7–1 | 低于 0.7 | 主图 · 价格 · 评分 |
| ② 转化率 | 指数 ≥ 1 | 0.7–1 | 低于 0.7 | 详情页 · 尺码 · 评价 |
| ③ 退货率（倍于标准） | ≤ 1 倍 | 1–1.3 倍 | 高于 1.3 倍（例：高于 32.5%） | 产品本身 · 版型 |

刻度 0.7 / 1 / 1.3 ✅；「偏低」档位的处置文字为「偏低，可修边」✅。

**闸门结论**：任一闸门被拦截 → 报告首页结论写「先别调广告」，所有加法类块（14 广告位加成、27 收割、28 重搭架构）顶部加提示条「闸门未过，这一块先只看不做」。✅

### 3.3 标品 / 非标品

| 指标 | 规矩 |
| --- | --- |
| 点击最多的 10 个搜索词占全部点击 | ≥ 50% 偏标品；≤ 30% 偏非标品；中间为混合 ✅ |
| 辅助：Top1 词点击占比、有点击 / 出过单的搜索词数、Top1 词订单占比 | 只展示，不单独判定 |

打法：标品 = 集中预算打核心大词，用精准匹配，抢搜索结果顶部，排不到前面基本没单；非标品 = 广泛和词组铺词，不死守顶部。✅

### 3.4 投放目的与容忍度

| 目的 | 包含 | 标准 | 判定标签 |
| --- | --- | --- | --- |
| 推排名 | 精准关键词 | 允许亏，ACOS ≤ 推排名上限（例 45.2%），用来换自然位 | 不亏 / 亏，在允许范围内 / 亏过上限 |
| 找词 | 自动、广泛（词组） | 必须不亏（ACOS ≤ 真实保本），用来发现新词 | 不亏 / 亏损，要止血 |
| 截流 | 商品定向、展示型 SD | 必须不亏 | 不亏 / 亏损，要止血 |

活动归类按命名规则和投放类型自动识别，识别不了的列出来请用户确认。🔶

### 3.5 样本量规矩

- 广告位加成：某活动某广告位 订单 ≥ 3，或 点击 ≥ 50 且 0 单，才下结论；否则标「样本不足，不调」。🔶（截图：25 点击 2 单、29 点击 1 单都判样本不足；68 点击 3 单可判；82 点击 0 单判加成归零）
- 变体：广告点击 ≥ 30 才判定，否则「样本不足，再看」。🔶
- 零单搜索词：见 3.6。
- **哪些要每款重算**：零单点击阈值（初筛 / 终判）、零单花费阈值、可承受 CPC 都随本款基准 CVR、成交价、保本线变化，**每次诊断都重算**；上面广告位、变体的订单 / 点击门槛是通用口径，不随款变。
- **近 7 天归因未闭合**：最近 7 天的订单还没补齐，不能单凭近 7 天判「恶化」。有两份覆盖同一日期的快照时，算订单补齐系数（后一份订单 ÷ 前一份订单）校正。🆕
- 位置、词的结论靠近门槛时，附 95% 置信区间（Wilson）和「再多 1 单，ACOS 变成多少」的敏感性，让结论的脆弱性可见。🆕

### 3.6 零单搜索词三分法 ✅（v0.3 改为两段式阈值）

| 处置 | 条件 | 说明 |
| --- | --- | --- |
| 买错了人：否定（确定级） | 点击 ≥ 终判阈值（≈ 2.3 ÷ CVR），仍 0 单 | 90% 把握转化率低于基准 |
| 买错了人：否定（初筛级 · 低预算路径） | 点击 ≥ 初筛阈值（1.5 ÷ CVR），仍 0 单，且花费 ≥ 零单花费阈值 | 低预算下宁可早否；报告标「初筛级」，回填时复核 |
| 买贵了：降价重试 | 花费 ≥ 零单花费阈值，点击 低于初筛阈值；或有单词的 CPC 高于可承受 CPC | 还没证明不转化，但这个价位已经亏；降到可承受 CPC 以内 |
| 样本不足：再看 | 花费 低于零单花费阈值 | 单个词花得少，逐个否定没有意义，交给词根复核（块 26） |

非低预算路径（用户明确说预算充足）时，只有终判级进入否定，初筛级降为「降价重试」。

不要为了凑动作放宽阈值：8028 款 253 个零单词只有少数达到证据线是正常结果。

**否词四步审计（每个要否的词都过一遍）** 🆕

1. **列载体**：该词在所有活动里的点击、花费、订单、ACOS，按花费排序（否词是活动级设置，同一个词会被多个活动命中）。
2. **标状态**：只否在投的活动，已停的不用否。
3. **算覆盖**：计划覆盖了该词多少花费占比；漏掉「占比最高且 ACOS 最差」的载体是最严重的错误，必须单独点出。覆盖率以报告实测为准，不按记忆。
4. **定形式**：默认**否定词组**；词无常见变体时用否定精准；**否定词根风险最大**，除非整个词族都核实过差，否则只作「人工语义复核候选」。用词族全家桶（单复数、修饰词、for 变体）验证误伤。

否词按**全店口径**判定（该词在所有活动合计仍零单才算），不按单活动口径。

### 3.7 广告位加成算法 🔶

- 每次点击销售额 RPC = 该位置广告销售额 ÷ 点击。
- 倍数 = 该位置 RPC ÷ 该活动整体 RPC。
- 建议加成 = (倍数 − 1) ÷ 2（半步调整，截图：倍数 1.91 → +46%，倍数 1.10 → +5%）；倍数低于 1 或 0 单 → 加成归零；站外位置标「站外不能设」。
- 建议与当前加成比较：「现在加少了 / 加多了 / 维持」。
- **ACOS 三级口径必须标注** 🆕：全活动合计 / 广告位（活动类合计）/ 单活动 × 广告位。三层常给出相反的动作，下结论前上下各校验一层。默认动作 = **砍最差的那个位置，保留整体达标的活动**，不因一个位置差而关整个活动。
- **平台事实** 🆕：广告位加成没有负数，最低 0%；固定竞价下也能设广告位加成。要压低某个位置的花费只有三条路：① 加成设 0% 并同时降基础竞价；② 降基础竞价（会影响所有位置）；③ 动态竞价改「只降低」（平台自动，不可精确控制）。
- 位置性格会变：上月的位置结论不能直接沿用，每次重算。🆕

### 3.8 暂停回顾 ✅

| 标签 | 条件 |
| --- | --- |
| 停得对 | 暂停前 ACOS 超过它所属目的的标准 |
| 停可惜了 | 暂停时不亏（ACOS ≤ 真实保本），值得重开 |
| 停早了 | 点击太少，零单只是运气，没测出结果 |
| 可以商量 | 推排名的活动，亏损在允许范围内 |

**死因分类（按证据充分性，不按 ACOS 高低）** 🆕

| 代号 | 死因 | 判定 | 结论 |
| --- | --- | --- | --- |
| A | 样本不足 | 0 单，花费 低于零单花费阈值，点击 低于初筛阈值 | 停早了，依据不成立 |
| B | 零单烧钱 | 0 单，花费 ≥ 零单花费阈值 | 停得对 |
| C | 效率严重不达标 | ACOS 高于真实保本 × 1.6 | 停得对 |
| D | 效率略超线 | 真实保本 低于 ACOS ≤ 真实保本 × 1.6，且有单 | 疑似停早，重点复盘（超线 ≤ 5pt 记 D1，超过 5pt 记 D2） |
| E | 停错 | ACOS ≤ 真实保本，且有单 | 停可惜了 |

- 已停活动**不能一刀切排除**，它是最好的对照组：新旧活动按「同一投位 / 同一改动逻辑」配对，旧 0 单 → 新有单 = 可复制动作；旧 0 单 → 新 0 单 = 无效动作，别再试。
- **关停前兆**：末日展示占比 = 最后一天展示 ÷ 前 6 天日均展示；低于 0.3 说明展示先枯竭，ACOS 恶化只是结果。在投活动出现这个信号直接进「观察」。（0.3 为 C 级实测值，见 3.9）
- 列关停清单前先按「状态 + 结束日期」过滤，已停活动不能算进可节省金额。

### 3.9 常数分级（引用任何数字前先看级别）🆕

| 级别 | 含义 | 例子 | 用法 |
| --- | --- | --- | --- |
| A 定义 | 公式推出来的，恒成立 | 保本 ACOS、可承受 CPC、二项检验阈值 | 直接用 |
| B 机制 | 平台规则或机制决定 | 归因窗口 7 / 14 天、加成最低 0% | 直接用，平台改规则时更新 |
| C 实测 | 某个产品某段时间测出来的 | 末日展示占比 0.3、单数词 CVR 高于复数、闸门刻度 0.7 / 1.3 | 必须标「产品 + 时间窗 + 样本量」，换款要重验 |

### 3.10 趋势判定：三态 + 五条硬标准 🆕

| 状态 | 判据（三条满足两条） | 动作 |
| --- | --- | --- |
| 优化中 ↗ | ① ACOS 逐段下降 ② CVR 逐段上升 ③ CPC 持平或下降 | 保留，可考虑加预算（再过 5.1 三条件） |
| 波动 ↔ | 无单调趋势，各段 ACOS 差异 低于 15% | 观察，不动作（「波动」是合法结论） |
| 恶化中 ↘ | ① ACOS 逐段上升 ② CVR 逐段下降 ③ 订单逐段下降 | 先归因，再处置 |

1. **量线、效率线分开判**：量 = 展示 / 点击 / 订单；效率 = CVR / ACOS / CPC。「订单降 + ACOS 降」是量在萎缩，不是变好。
2. **用累计口径，不用日值**：时间窗切 4 段看累计值；样本 低于 100 次点击时，禁止用日值下趋势结论。
3. **恶化先归因到量 / 效率 / 成本**：

| 症状 | 归因 | 处置方向 |
| --- | --- | --- |
| 展示↓ + 点击↓ | 竞价 / 竞争力不足 | 提竞价（闸门已过时） |
| 展示稳 + 点击↓ | CTR 下滑 = 位置下滑 | 查广告位加成 |
| 点击稳 + CVR↓ | 承接力下降（链接、价格、竞品） | 改词或改链接，不是改竞价 |
| CVR 稳 + CPC↑ | 成本上涨（竞争加剧） | 降竞价 / 收窄位置 |
| 展示↓ + 订单↓ + ACOS↓ | 量在萎缩（最危险） | 立刻处置，别被 ACOS 骗 |

4. **最后一段剔除或标注未补齐订单**（见 3.5）。
5. **判定前先问改动记录**：这段时间用户改过什么、什么时候生效；改动前后分段看，新老活动分表判定。

**「花费花不出」先分型，不直接提竞价或加预算**：展示跌 + 点击跌 → 竞价不足；展示稳 + 点击跌 → 位置下滑；展示点击都稳 → 只是 CPC 降了，正常；双双大跌 → 查预算触顶或季节需求。

## 5. 行动清单生成规则 ✅

按以下优先级生成，没有命中的条目跳过；每条写清「编号 + 做什么 + 涉及对象 + 金额 + 依据 + 判定线 + 复盘日期」。同一优先级内，再按**操作成本**分组（① 后台点几下就能改：降价、否词、改加成 → ② 要新建或调整活动 → ③ 要改 listing / 产品），不按证据强弱分组：

1. **闸门问题**（如退货率超标，停止放量）：写出本款数值、标准、问题最集中的尺码 / 颜色、退货原因是否集中在偏大偏小 → 是就归工厂改版。
2. **停掉落错地方的变体广告**（块 18）：列变体和合计花费。
3. **加否定词根**（块 26）：列候选数和花费最高的 5 个词根；提示人工过一遍再加到自动和广泛活动。
4. **给买贵了的词降价**（块 25）：降出价重试，不是暂停。
5. **给找词和截流的亏损活动止血**（块 7、8）：列活动和 ACOS。
6. **推排名的精准活动里，亏过上限的降价**。
7. **推排名的精准活动在允许范围内亏的，先保留、盯自然位**：两周后看这些词的自然位有没有往前走，没动就降价。
8. **重开停可惜了的关键词**（块 31）：这是把停掉的恢复，不算新增投放。
9. **暂缓：加法类动作全部暂缓**（仅当闸门未过时出现）：收割出单词、加广告位加成、提预算、开新活动，等闸门问题解决后再做。

### 5.1 动作纪律 🆕

**加预算（三条件同时满足）**

1. ACOS ≤ 达标线（真实保本 × 75%）；
2. 预算确实不够用：预算报告「预算范围内的平均时间」低于 80%，或活动经常在当天中途耗尽预算（该列导出后常为 0 / 缺失，此时看耗尽时刻）；
3. CVR 高于盈亏 CVR（= CPC ÷ (真实保本 × 平均成交价)）。

满足后分四档、每档 +20%，每档观察 7 天，事先写死总花费上限。推排名实验的预算只在实验上限内调整，不走这条。

**ACOS 变好先分原因**：CVR 升了 → 可以加；CPC 降了 → 谨慎（可能是丢了好位置）；订单降了 → 绝不加。

**降预算先算饱和度**：实际花费 ÷ 预算 低于 60% 的活动，砍预算等于没操作；要降 ACOS 降的是竞价（整体 20–25%，边际损失先丢低效展示），不是预算。腾预算按饱和度从高往低砍，目标函数是「实际月花费」不是「预算额」。

**关停前：承接链体检四问**

1. 这个活动承载了哪些词，各占该词花费多少（占比超过 50% = 高风险词）？
2. 这些词的其他载体是谁、是否在投、效率如何？
3. 其他载体合计占比 低于 30% → 接不住，先建好承接再关。
4. **承接方比被关方更好还是更差？**（决定性问题）更好 → 放心关；更差 → 一起放弃该词，不单独开活动追。

**关停护栏**：关停前 5 天内出过单 → 不直接关，改降竞价观察；批量关停也要逐个标死因（3.8）。

**方案对比**：止损类动作至少比较「不动 / 关掉 / 降竞价 / 降竞价 + 清词」，各算花费、订单、ACOS、广告后毛利。

**加价看展示量份额排名**：份额排名 ≥ 4 且该词达标 → 可以加价；排名 ≤ 3 → 不加（已经在前排，加价只抬 CPC）。份额 % 只用来反推词池空间（词池总展示 ≈ 我的展示 ÷ 份额），并识别「小池子里的假高份额」。

**竞价策略跟生命周期走**：新品期 L0 固定竞价 → 爬坡 L1 提高和降低 → 成熟 L2 只降低 → 衰退 L3 只降低 + 降预算。竞价锚点统一用建议竞价下限；新建活动 7 天内不动。

### 5.2 回填闭环 🆕

- 每条动作带编号（如 `8028-1017-01` = 款号 - 日期 - 序号）、数值化判定线（如「7 天后 ACOS ≤ 22.6% 且订单不降」）、观察期（默认 7 天；期内点击 低于 100 自动延期）。
- 出报告时同时预填**动作台账**：编号、动作、对象、改动前数值、判定线、复盘日期、结果（✅ 成立 / ❌ 不成立 / ⚪ 判不了）、改进项。❌ 必填改进项。
- 同一对象一次只改一个变量，避免判定线被其他动作掩盖导致「判不了」。
- 下一次诊断开头先回填上次台账，再做新诊断。

### 5.3 载体与架构 🆕

- **定投 vs 关键词没有固定答案**：同一组目标分别用两种载体跑、按可承受 CPC 和 CVR 比较；结论随生命周期翻转（新品以关键词 / 搜索词为主力，成熟期定投常更高效）。
- 活动骨架由「流量结构 × 单一目标」推出，每个活动只承担一个目的（推排名 / 找词 / 截流），便于按 3.4 判容忍度。
- **出架构必须同时出词表**，出词表必须同时说明放进哪个活动。
- 新建活动的数据量自检：词数 × 7 天 × 日均点击 ≥ 28，否则 7 天内得不出结论，应减词或合并。

## 6. 报告输出规范

- **格式**：单文件 HTML（可离线打开），同时在对话里给出首页结论和行动清单的文字版。
- **页头**：「广告漏斗诊断 Skill」小标签；标题「{款号} 款 · 广告诊断报告」；元信息：站点、类型（偏标品 / 偏非标品）、对象（N 个变体 · M 个在投活动）、时间（近 30 天，到 YYYY-MM-DD）、数据源、生成时间。
- **导航**：7 个大 Tab（首页 + 5 章 + 附 · 规矩表，每个 Tab 带一行副标题）；章内用编号胶囊切换块；每块底部有「← 上一块 / 下一块 →」和页码「n / 31」。
- **视觉**：浅青底 `#F3FAF8` + 白卡片；页头是青 → 蓝渐变圆角卡（`#14B8A6 → #3B82F6`）；语义色：通过 / 不亏 = 青绿 `#14B8A6`，偏低 / 待确认 = 琥珀 `#F59E0B`，拦截 / 亏损 = 珊瑚红 `#F2545B`，信息 = 蓝 `#3B82F6`，中性 = 灰 `#B6C3C0`；数字统一等宽字体 + tabular-nums；判定标签用小色块。完整 token 与组件清单见附录 A。
- **页脚**：「本报告由广告漏斗诊断 Skill 生成 · 只读取数据，不修改任何广告 · 判定依据见「附 · 规矩表」Tab · 仅供内部决策参考」。第 3 节规矩表以独立 Tab 呈现，不放在正文末尾。

## 7. 执行步骤（给 AI）

1. 确认款号、站点、时间窗口、数据来源；向用户索取缺失的货值头程和类目基准。
   - 先拆前提：用户问题里如果带隐含前提（如「这个词 B 活动会接住」），先校验再回答。🆕
   - 先问真实意图和近期改动：改了什么、什么时候生效、想达到什么。🆕
   - 先切时间轴：一直差还是变差了（第 1 节第 7 条）。新品 0 单先分流量问题（展示 / 点击不够）还是承接问题（有点击无单），承接问题不调广告。🆕
   - 有上次的动作台账 → 先回填（5.2）。🆕
2. 读取并清洗数据：统一 ASIN、活动名、日期；剔除未补齐的最近 2–3 天订单（或在表中标注）。产品边界按推广的 ASIN 归属，穷举 SP / SB / SBV / SD 全部活动，**不按活动名前缀划**；输出「未能归属的活动：N 个」，N 为 0 才往下。🆕
3. 先算第 3 节全部口径（保本线、阈值、闸门指数），写入规矩表。
4. 按块 1→31 依次计算；每块先写「怎么判断」，再出表和判定。
5. 汇总生成首页结论卡、三闸门卡、钱的卡片和行动清单。
6. 渲染 HTML，自检后交付。

## 8. 账户总览（多父体）

- 先对每个父体跑一遍第 1 章（保本线 + 三道闸门），再汇总成一张总表：父体、类型、广告花费、ACOS、TACOS、真实保本、卡在哪道闸门、建议。
- 分组：**可加预算**（闸门全过且 TACOS 低于保本）/ **只做减法**（任一闸门拦截）/ **观察**（偏低档或样本不足）。
- 账户层只给预算倾斜方向，具体动作仍在各父体的单父体报告里。
- 活动归属以推广 ASIN 为准，不按活动名前缀；别的产品线的浪费不能算到本父体头上。🆕

## 9. 广告类型口径（SP / SB / SD）

| 类型 | 归因窗口 | 归类到 | 额外指标 |
| --- | --- | --- | --- |
| SP 商品推广 | 7 天 | 按投放方式归推排名 / 找词 / 截流 | 广告位、搜索词 |
| SB 品牌推广 | 14 天 | 默认归推排名（品牌词归「防守」） | 新客订单占比、品牌搜索量、视频完播（视频广告） |
| SD 展示型推广 | 14 天（浏览归因需单列） | 默认归截流 | 点击归因 vs 浏览归因分开，VCPM 活动单独看 |

SB、SD 与 SP 合并计算 ACOS 时必须注明归因窗口不同；TACOS 用全部广告花费。

## 10. 数据接入方式

| 方式 | 适合 | 说明 |
| --- | --- | --- |
| A. 手动上传报表 | 先跑起来 | 广告后台和卖家后台导出 CSV / XLSX，直接拖进 Notion AI 对话即可 |
| B. 亚马逊官方 Amazon Ads MCP | 广告数据自动取数 | 需要 Ads API 权限（Client ID + Refresh Token），在 Notion 里作为自定义 MCP 连接 |

退货报告、付款报告（真实保本线用）通常仍需从卖家后台导出，或经由 SP-API / ERP 接口取得。

## 附录 A · HTML 实现规范（复刻用）

**文件形态**：单文件 HTML，可离线打开。三段结构 = `<style>`（CSS 全内联）+ `<body>`（页头 / 导航容器 / `<main>` / 页脚）+ `<script>`。

**数据容器**：正文不写死在 HTML 里，而是嵌一个 JSON 数组 `const SC=[...]`，形状：

```
[ { id, name, sub, ch: [ { t, s, blocks: [ { n, name, html } ] } ] } ]
```

- 作用域（账户 / 各款）→ 章 → 块；`blocks[].n` 是块号（首页为空串），`html` 是该块完整的 HTML 片段。
- 导航由约 30 行 JS 渲染：作用域按钮、章 Tab、块胶囊、「← 上一块 / 下一块 →」、`location.hash = 作用域-章-块`（可直接用 `#1-3-1` 打开第 3 章第 2 块）。

**设计 token（照抄即可）**

```
--bg:#F3FAF8  --card:#fff  --line:#E2EEEB  --ink:#1F2D2B  --sub:#5F716D
--teal:#14B8A6 --tealD:#0B7F73 --tealS:#E0F7F3
--sky:#3B82F6  --skyS:#E6F0FF
--sun:#F59E0B  --sunD:#9A5B00  --sunS:#FFF4DB
--coral:#F2545B --coralD:#C9343B --coralS:#FFE8E8
--grape:#8B5CF6 --grapeS:#F1EBFF
```

- 页头：青 → 蓝渐变圆角卡（`linear-gradient(120deg,#14B8A6,#3B82F6)`），右上角半透明圆做装饰。
- 正文：15px / 1.55，系统中文无衬线；`.wrap` 最大宽 1120px。
- 所有数字包 `.num`（等宽字体 + tabular-nums），保证纵向对齐。

**组件清单（每块都用这几个拼）**

| 组件 | 类名 | 用途 |
| --- | --- | --- |
| 页头 | `header` / `.tag` / `h1` / `.meta` / `.demo` | 小标签 + 标题 + 元信息 + 缺失数据提示条 |
| 作用域切换 | `.scope button` | 账户总览 / 各款 |
| 章 Tab | `nav.tabs` | 首页 + 5 章 + 附录 |
| 块胶囊 | `.pills` | 章内切块 |
| 结论卡 | `.hero` + `.chips` | 首页大字结论 + 右侧说明 + 标签条 |
| 卡片 | `.card h2` | 每块的容器（标题含块号 `.no`） |
| 规矩条 | `.how` | 「怎么判断」一句话（灰底） |
| 判定卡 | `.verdict` + `ok/warn/bad/info/mute` | 判定结论 + 一句说明 |
| 指标格 | `.kpi` | 12 格 KPI |
| 闸门卡 | `.gate` | 指数大数字 + 刻度条 + 我 vs 基准 |
| 数据表 | `.tw table`，数字列 `class="r num"` | 所有数据表 |
| 判定标签 | `.b` + `ok/bad/warn/info/mute` | 行内小色块 |
| 提示条 | `.miss` / `.miss.part` / `.hold` | 数据缺失 / 部分缺失 / 加法暂缓 |

**配色语义**：通过 / 不亏 = teal；偏低 / 待确认 = sun；拦截 / 亏损 = coral；中性 = mute；信息 = sky。

**每块的写法顺序**：规矩条 `how()` → 判定卡 → 数据表 → 判定标签列；表格默认按花费降序。

**对照样板**：`examples/amazon-telly-ad-funnel-diagnosis-sample-report.html`（31 块全量、数据虚构），可逐个块对照要长成什么样。
